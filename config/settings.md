# config/settings.json 설정값 안내

`config/settings.json`은 이 프로그램의 모든 설정값을 모아둔 파일입니다.
JSON 파일은 문법상 주석(`//`, `#` 등)을 쓸 수 없고, 프로그램이 설정을
저장할 때마다(예: 튜닝 화면에서 '저장' 클릭) 파일 전체를 새로 써버리기
때문에 JSON 파일 안에 직접 주석을 달아도 남지 않습니다. 그래서 각 값의
뜻은 이 문서에 정리해둡니다.

값을 직접 이 파일에서 고쳐도 되지만, `detection`(HSV 프로필)과
`calibration`의 매트 크기·매트 밖 필터는 프로그램 안의 **설정 메뉴**
(검출 설정.../프로필·매트 설정...)에서 바꾸는 게 더 안전합니다 - 실수로
JSON 문법을 깨뜨릴 위험이 없고, 화면으로 바로 결과를 확인할 수 있습니다.

## camera - 카메라 입력 설정 (`src/camera.py`)

카메라를 열 때 요청할 값들입니다. 카메라/드라이버가 요청한 값을 그대로
지원하지 않으면 다른 값으로 맞춰질 수 있는데, 실제로 적용된 값은
프로그램 실행 시 터미널에 `[카메라] 적용된 설정 -> ...`로 출력됩니다.

- **width, height**: 요청할 영상 해상도(가로·세로, 픽셀). 예: `1920`, `1080`.
  이 카메라는 `1280x720`으로 열면 센서 가운데만 잘려 매트 일부만 보이므로
  `1920x1080`(MJPG)으로 엽니다. 처리 속도는 아래 `process_scale`로 맞춥니다.
- **fps**: 요청할 초당 프레임 수. `0`이면 카메라 기본값을 그대로 쓰고
  따로 요청하지 않습니다.
- **use_mjpg**: `true`면 카메라에 MJPG(압축) 포맷을 요청합니다. USB
  카메라는 대부분 압축 안 된 포맷(YUY2 등)으로는 고해상도·고FPS를 동시에
  내기 어려워서, 보통 `true`로 둬야 실제로 높은 FPS가 나옵니다.
- **rotate**: 카메라가 옆으로/거꾸로 설치된 경우 보정할 회전 각도.
  `0`, `90`, `180`, `270`(시계 방향) 중 하나만 쓸 수 있고, 그 외 값은
  회전 없음으로 처리됩니다. 회전은 카메라에서 프레임을 읽어온 직후
  (전처리 첫 단계로) 적용되므로, 이후 공 검출·궤적·좌표 계산은 모두
  이미 회전된 화면 기준으로 동작합니다.
- **process_scale**: 카메라 영상을 처리할 때 줄이는 비율 (`src/lens.py`).
  기본값 `0.75` (1920x1080 → 1440x810). 카메라는 넓게(1920x1080) 받고,
  공 검출은 줄인 영상으로 해서 처리 시간을 줄입니다. `1.0`이면 줄이지
  않습니다. 허용 범위 `0.1`~`1.0`. 값이 없으면(예전 설정 파일) `0.75`.
  - 값을 줄이면 빨라지지만 공이 화면에서 작아집니다. 22단계 측정에서
    매트 끝 공의 면적이 0.75배일 때 약 190~210px², 0.5배일 때 약 70px²
    였습니다. 바꾸면 `detection`의 `min_area`/`max_area`도 함께 맞추세요
    (설정창의 "검출 디버그 표시"를 켜면 화면에 면적이 나옵니다).
- **undistort_k1**: 렌즈 왜곡 보정 값 (`src/lens.py`). 광각 렌즈 때문에
  매트 테두리가 활처럼 휘어 보이는 것을 펴 줍니다. `0`이면 보정하지
  않습니다(기본값). 음수(-)는 가운데가 부풀어 보이는 '술통형' 왜곡을,
  양수(+)는 반대 방향 왜곡을 폅니다. 직접 고치기보다 **설정 > 프로필/매트
  설정... > 렌즈 왜곡 보정** 슬라이더로 격자선을 보며 맞추고 '저장'하는
  것을 권장합니다. 이 카메라는 약 `-0.50`에서 가장 곧게 펴졌습니다
  (`-0.59`보다 작으면 화면 좌우 끝이 접혀 의미가 없음).

> 처리 순서: 회전 → 축소(`process_scale`) → 왜곡 보정(`undistort_k1`).
> 공 좌표·캘리브레이션 모서리·화면 표시·앱의 ALIGN corners는 모두 이
> 전처리가 끝난 화면 기준 픽셀 좌표입니다. 그래서 `process_scale`이나
> `undistort_k1`을 바꾸면 **캘리브레이션을 다시 해야 합니다** (프로그램이
> 알아서 감지해 로그와 화면에 알려 줍니다).

## detection - 공 검출(HSV 색상) 설정 (`src/detector.py`)

카메라 화면에서 공을 어떤 색 범위로 찾을지 정하는 값들입니다. 조명이나
공 색이 바뀌면 이 값들을 다시 맞춰야 하는데, JSON을 직접 고치기보다는
**'설정 > 검출 설정...'**의 HSV 슬라이더로 조정하고 저장하는 것을
권장합니다.

- **active_profile**: 지금 실제로 사용 중인 프로필의 키(예: `"practice_lime"`).
  `profiles` 아래 있는 키 중 하나를 가리켜야 합니다.
- **profiles**: 여러 개의 HSV 설정을 이름 붙여 저장해둔 목록(예: 연습용
  흰 공, 실전용 분홍 공 등을 각각 만들어두고 상황에 따라 전환). 각
  프로필은 다음 값을 가집니다.
  - **name**: 화면(프로필 목록, 저장 기록)에 보여줄 사람이 읽기 쉬운
    이름. 예: `"연습용 (연두 공)"`.
  - **hsv_lower, hsv_upper**: 공 색으로 인식할 HSV 색 범위의
    하한/상한 `[H, S, V]`. OpenCV 기준으로 H(색상)는 0~179,
    S(채도)·V(명도)는 0~255. 이 범위 안에 들어오는 픽셀만 "공일 수
    있는 영역"으로 본다. 범위를 넓히면 더 잘 잡히지만 배경의 비슷한
    색도 같이 잡힐(오검출) 위험이 커진다.
  - **min_area, max_area**: 색 범위로 찾은 덩어리(윤곽선) 중, 넓이가
    이 범위(픽셀² 단위) 안에 있는 것만 공 후보로 인정한다. 너무 작으면
    노이즈, 너무 크면 배경 전체가 잡힌 것으로 보고 무시한다. 단위가
    **처리 화면(축소 후) 픽셀**이라 `camera.process_scale`을 바꾸면 함께
    바꿔야 한다. 기본 `80`~`600`(0.75배에서 공 약 200px² 기준).
  - **min_circularity**: 덩어리가 얼마나 원에 가까운 모양인지(0~1,
    1이 완전한 원). 이 값보다 원에 가까운 덩어리만 공으로 인정해서,
    둥글지 않은 물체(그림자, 손 등)를 걸러낸다.

## tracking - 추적·정지 판정 설정 (`src/tracker.py`)

공의 이동을 궤적으로 기록하고, 언제 "멈췄다"/"화면을 벗어났다"로 볼지
정하는 값들입니다. 단위는 모두 **픽셀**(캘리브레이션 전 화면 좌표)
기준입니다.

- **min_move_distance**: 직전에 기록한 점과 이 거리(픽셀)보다 가깝게
  움직이면 새 점으로 기록하지 않는다. 너무 촘촘하게(거의 제자리) 점이
  쌓이는 것을 막는다.
- **max_jump_distance**: 직전 점과 이 거리(픽셀)보다 멀리 떨어진
  검출은 일단 오검출(잘못 찾음)일 수 있다고 보고 궤적에 바로 반영하지
  않는다. 값이 너무 작으면 빠르게 구르는 공의 점을 계속 걸러내
  궤적이 끊기고, 너무 크면 진짜 오검출까지 궤적으로 받아들여 궤적이
  갑자기 튈 수 있다.
- **max_consecutive_jumps**: `max_jump_distance`를 넘는(멀리 떨어진)
  값이 연속으로 이 횟수 이상 나오면, 더는 오검출이 아니라 "공을
  실제로 다른 곳에 옮겨놨다"고 보고 그 위치를 받아들인다.
- **stop_threshold**: 두 프레임 사이 공의 이동 거리가 이 값(픽셀)
  이하이면 "거의 안 움직였다"로 본다.
- **stop_duration**: 공이 `stop_threshold` 이하로만 움직이는 상태가
  이 시간(초) 이상 계속되면 "정지"로 판정하고 추적을 자동으로
  끝낸다(FINISHED로 전환).
- **lost_duration**: 공이 화면에서 검출되지 않는 상태가 이 시간(초)
  이상 계속되면 "화면 이탈"로 판정하고 추적을 자동으로 끝낸다.
- **arm_move_distance** (기본 8): '추적 준비'(앱의 `ADD`) 후 추적 대기
  (ARMED) 상태에서, 공이 **시작 위치에서 이 거리(픽셀) 이상** 움직이는
  순간 자동으로 추적(TRACKING)을 시작한다. 대기 중에는 정지·이탈 판정을
  하지 않으므로 퍼팅 전에 공이 오래 가만히 있어도 추적이 끝나지 않는다.
  값이 너무 작으면 검출 좌표의 흔들림(보통 1~3픽셀)에 추적이 멋대로
  시작되고, 너무 크면 공이 꽤 굴러간 뒤에야 시작된다. 이 항목이 파일에
  없으면 기본값 8을 쓴다.

## calibration - 매트 캘리브레이션 설정 (`src/calibration.py`)

카메라 화면의 픽셀 좌표를 실제 매트 위의 mm 좌표로 바꾸기 위한 값들.
`corners`와 `perspective_matrix`는 프로그램의 **'캘리브레이션'** 버튼으로
매트 네 모서리를 화면에서 클릭하면 자동으로 계산되어 저장되므로, 직접
손으로 입력할 값이 아니다.

- **mat_width_mm, mat_height_mm**: 실제 매트의 가로·세로 크기(mm).
  '설정 > 프로필/매트 설정...'에서 바꿀 수 있고, 여기서 바꾸면 이미
  찍어둔 네 모서리(`corners`)를 다시 클릭하지 않아도 새 크기 비율로
  변환 행렬이 다시 계산된다.
- **filter_outside_mat**: `true`면 캘리브레이션한 매트 사각형 밖에서
  검출된 공은 오검출로 보고 무시한다(궤적에 기록하지 않음). 매트
  주변 물체를 공으로 착각하는 것을 막아준다.
- **corners**: 캘리브레이션 중 클릭한 매트 네 모서리의 화면 픽셀 좌표
  `[[x, y], ...]` 4개. 순서는 좌상단 → 우상단 → 우하단 → 좌하단.
- **perspective_matrix**: `corners` 네 점으로부터 계산된 3x3 원근
  변환 행렬. 카메라 화면 픽셀 좌표를 매트 위 실제 mm 좌표로 바꿀 때
  이 행렬을 사용한다(카메라가 매트를 비스듬히 내려다봐도 정확한 실제
  거리를 계산할 수 있게 해준다).
- **frame_size, undistort_k1**: 이 `corners`를 찍었을 때의 처리 화면
  크기 `[가로, 세로]`와 렌즈 왜곡 보정 값. 캘리브레이션을 저장할 때
  자동으로 기록됩니다. 프로그램 시작 시 지금 값(`camera.process_scale`로
  줄인 크기, `camera.undistort_k1`)과 다르면 저장된 모서리가 화면과 맞지
  않으므로 "캘리브레이션 안 됨"으로 취급하고 다시 하라고 알려 줍니다.
  이 두 값이 없는 예전(21단계까지) 설정도 같은 이유로 다시 해야 합니다.

## protocol - 메인 컨트롤과의 통신 설정 (`src/protocol_server.py`, `src/protocol_handler.py`)

메인 컨트롤 프로그램(Flutter 등)이 TCP로 접속해서 JSON 명령을 보내고
좌표·상태를 받는 통신 설정입니다. 메시지 규격은 `docs/PROTOCOL.md`를
보세요. `enabled`, `port`는 설정 창(설정 > 프로필/매트 설정... > 앱 통신
설정)에서도 바꿀 수 있고, 나머지는 파일을 고친 뒤 프로그램을 다시
시작해야 적용됩니다.

- **enabled** (기본 `true`): 통신 서버를 켤지 여부.
- **port** (기본 `9000`): 접속 포트. 다른 프로그램이 이미 쓰고 있으면
  서버를 열지 못한다(화면 없이 실행하면 오류 문구를 출력하고 종료 코드 2로 끝난다).
- **addr_radius_mm** (기본 `100`): 어드레스 위치(`SET_ADDR`)를 중심으로
  이 반경(mm) 안에 공이 들어오면 `ADDR IN`, 반경의 1.2배 밖으로 나가면
  `ADDR OUT` 이벤트를 보낸다. `SET_ADDR`의 `radius_mm`으로 덮어쓸 수 있다.
- **status_hz** (기본 `30`): 추적 중(TRACKING) 실시간 `STATUS`를 초당
  최대 몇 번 보낼지. 상태가 바뀔 때는 이 값과 상관없이 바로 보낸다.
- **result_points** (기본 `true`): 추적이 끝났을 때 보내는 `RESULT`에
  궤적 점 전체(`points`: 점마다 `[x_mm, y_mm, 경과시간, 누적거리, 속도]`)를
  함께 실을지. `false`면 요약값(총 거리·평균/최고 속도 등)만 보낸다
  (메시지를 작게 하고 싶을 때).

## logging - 로그 설정 (`src/log_setup.py`, `src/engine.py`)

엔진이 무엇을 했는지(시작·접속·명령·추적·카메라 끊김·오류)를 파일
`logs/engine.log`와 콘솔에 남기는 설정입니다. 화면 없이 오래 돌아가는
프로그램에서 문제가 생겼을 때 "그때 무슨 일이 있었는지" 확인하는 용도입니다.
exe로 묶으면 콘솔 창이 없어서 이 파일이 유일한 단서가 됩니다.
이 항목이 파일에 없으면 아래 기본값을 씁니다 (프로그램을 다시 시작해야 적용).

- **level** (기본 `"INFO"`): 어디까지 남길지. `"DEBUG"`(상태 조회·연결 확인까지 전부) /
  `"INFO"`(평소 운영) / `"WARNING"`(문제만) / `"ERROR"`(오류만).
- **max_bytes** (기본 `1048576` = 1MB): 로그 파일 하나의 최대 크기. 넘으면
  `engine.log.1`, `engine.log.2`로 넘기고 새 파일에 이어 쓴다.
- **backup_count** (기본 `3`): 보관할 이전 로그 파일 수. 이보다 오래된 것은 지워서
  디스크가 가득 차지 않는다.
- **stats_interval_s** (기본 `10`): FPS와 프레임 처리 시간 요약을 로그에 남기는 간격(초).
  `0`이면 남기지 않는다. 예: `상태 요약 - FPS 72.6, 처리 시간 ... 평균 8.5ms 최대 59.7ms,
  카메라 OK, 접속 1대, 상태 IDLE, 오류 0번`. 처리 시간이 프레임 간격(FPS의 역수)보다
  길어지면 엔진이 카메라를 따라가지 못하고 있다는 뜻이다.

로그 폴더(`logs/`)는 Git에 올리지 않는다.

## storage - 측정 결과 저장 설정 (`src/storage.py`)

'저장' 버튼을 눌렀을 때 측정 결과를 기록하는 SQLite 데이터베이스 파일
위치입니다.

- **db_path**: 결과 DB 파일 경로. 프로젝트 폴더 기준 상대 경로(기본
  `"data/results.db"`)거나 절대 경로를 쓸 수 있다. 이 파일은 사용자가
  직접 만든 측정 기록이라 Git에는 올리지 않는다(`.gitignore`에
  `*.db`로 이미 제외되어 있음).
