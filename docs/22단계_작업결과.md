## 1. 왜 바꿨나

| 문제 | 내용 |
|---|---|
| 화각 | 카메라를 1280x720으로 열면 센서 가운데만 잘려서 매트 일부만 보인다. 1920x1080으로 열어야 매트 전체가 보인다. |
| 속도 | 1920x1080을 그대로 처리하면 느리다 (화면 모드 약 27ms, 33 FPS). 병목은 카메라가 아니라 공 검출 처리다. |
| 왜곡 | 광각 렌즈라 매트 테두리가 활처럼 휘어 보인다. 4점 원근 변환만으로는 매트 가운데 좌표가 어긋난다. |

**해결 방향**: 카메라는 1920x1080으로 넓게 받고, 처리할 때만 줄인 뒤 왜곡을 편 영상을 엔진 전체가 쓴다.

## 2. 구현 내용

### 2-1. 프레임 전처리 (`src/lens.py`, 신규)
- 처리 순서: **회전(rotate) → 축소(process_scale) → 왜곡 보정(undistort_k1)**
- 왜곡 보정용 좌표 지도(map)는 프레임 크기나 k1이 바뀔 때만 한 번 만들고, 매 프레임은 `cv2.remap`만 한다.
- k1 ≠ 0이면 축소와 왜곡 보정을 **remap 한 번으로 합쳐서** 처리한다. 결과는 "축소한 뒤 보정"과 같고 더 빠르다 (0.75배에서 전처리 6.6ms → 3.4ms).
- 카메라 행렬은 fx = fy = 프레임 폭, 중심 = 프레임 가운데로 가정한다. 왜곡 계수는 `[k1, 0, 0, 0, 0]`.
- k1 = 0이면 보정을 건너뛴다 (원본 그대로).
- 보정 후 화면 배율은 직접 계산한다. 원본의 상하좌우 끝(매트 양 끝)이 화면 안에 남도록 전체를 줄인다.
  - 처음에는 `cv2.getOptimalNewCameraMatrix(alpha)`를 썼다. 그런데 이 렌즈처럼 왜곡이 크면(k1 < 약 -0.55) 값이 크게 튀고 가로·세로 배율까지 달라져서 쓸 수 없었다.
- `src/camera.py`는 이제 원본 프레임만 읽는다. 회전은 전처리로 옮겼다.
- **엔진의 모든 픽셀 좌표는 전처리가 끝난 프레임 기준이다.** 공 검출, 시작점, 캘리브레이션 모서리, 화면 표시, 프로토콜 ALIGN corners가 모두 해당된다.

### 2-2. 설정 (`config/settings.json`의 `camera`)
```json
"camera": {
    "width": 1920,
    "height": 1080,
    "fps": 0,
    "use_mjpg": true,
    "rotate": 0,
    "process_scale": 0.75,
    "undistort_k1": 0.0
}
```
- `process_scale`: 기본 0.75 (1440x810), 허용 범위 0.1 ~ 1.0
- `undistort_k1`: 기본 0.0 (보정 안 함)
- 값이 없으면 기본값을 쓴다 (예전 설정 파일과 호환).
- 설명은 `config/settings.md`에 추가했다.

### 2-3. 캘리브레이션 무효화
- 캘리브레이션을 저장할 때 그때의 처리 화면 크기(`frame_size`)와 `undistort_k1`을 함께 저장한다.
- 엔진 시작 시나 값이 바뀌었을 때 지금 값과 다르면 "캘리브레이션 안 됨"으로 취급한다.
- 이때 로그와 화면 상단 경고 띠에 **"해상도/왜곡 보정이 바뀌어 캘리브레이션을 다시 해야 합니다"**를 띄운다.
- 크기·k1 기록이 없는 예전(1280x720 시절) 캘리브레이션도 자동으로 무효가 된다. 실제 실행 로그에서 확인했다.
- 슬라이더로 k1을 원래 값으로 되돌리면 저장된 캘리브레이션이 다시 살아난다.

### 2-4. 공 검출 크기 기준
- 모든 프로필의 `min_area`를 200 → **80**, `max_area`를 8000 → **600**으로 바꿨다. `src/detector.py` 기본값도 같이 바꿨다.
- 검출 디버그 표시를 추가했다. 색 범위에 맞은 덩어리마다 면적(A)·지름(D)·원형도(C)를 카메라 화면에 글자로 보여준다.
  - 흰 글자 = 공 조건 통과
  - 주황 글자 = 걸러짐

### 2-5. 설정창 "렌즈 왜곡 보정" (`src/ui/settings_dialog.py`)
- 위치: 설정 메뉴 > 프로필/매트 설정... > 렌즈 왜곡 보정
- k1 슬라이더: -0.60 ~ +0.50, 0.01 단위, 현재 값 표시
- 슬라이더를 움직이면 메인 화면의 카메라 영상에 바로 반영된다 (미리보기).
- **저장**을 눌러야 `settings.json`에 저장된다. **취소**하거나 저장하지 않고 창을 닫으면 이전 값으로 되돌린다.
- 같은 구역에 다음 두 가지 켜기/끄기가 있다.
  - "카메라 화면에 격자선 표시": 직선인지 판단하기 쉽게
  - "검출 디버그 표시 (공 면적·지름)"
- 기존 골프 테마(QSS)를 따른다. 경고 띠·구역 제목 스타일은 `src/ui/styles.py`에 추가했다.

### 2-6. 로그
- 상태 요약 로그에 다음 항목을 추가했다: 전처리 평균 시간, 처리 화면 크기, scale, k1

### 2-7. 프로토콜 2.3 (`docs/PROTOCOL.md`)
- `HELLO`에 `frame_w`, `frame_h`(처리 화면 크기)를 추가했다. 첫 프레임 전이면 `null`이다.
  ```json
  {"cmd":"HELLO","version":"2.3", ..., "frame_w":1440,"frame_h":810}
  ```
- `ALIGN corners`는 **전처리(축소·왜곡 보정) 후 화면 기준** 좌표라고 명시했다.
- 처리 조건이 바뀌면 `calibrated`가 `false`가 된다. 이때 `use_saved`는 `not_calibrated`로 거절된다.

## 3. 현장 측정 결과

### 3-1. 스케일별 FPS / 처리 시간
`logs/engine.log` 상태 요약, 10초 구간 평균이다.

| process_scale | 처리 화면 | 화면 모드 (`run_ui.bat`), k1=0 | 엔진만, k1=0 | 엔진만, k1=-0.50 |
|---|---|---|---|---|
| 1.0 | 1920x1080 | 33 FPS, 평균 26.7ms (최대 42ms) | 52 FPS, 15.4ms | 43 FPS, 20.3ms (전처리 5.1ms) |
| 0.75 | 1440x810 | 43 FPS, 평균 19.4ms (최대 39ms) | 52 FPS, 12.5ms (전처리 2.9ms) | 52 FPS, 12.1ms (전처리 2.9ms) |
| 0.5 | 960x540 | 56 FPS, 평균 7.7ms (최대 12ms) | 59 FPS, 4.4ms (전처리 0.7ms) | 58 FPS, 5.3ms (전처리 1.8ms) |

- 화면 모드는 영상 그리기 시간이 처리 시간에 포함돼 더 느리다.
- 평소 운영(엔진만)은 0.75에서 약 12ms다.
- 카메라가 약 60 FPS까지만 보내는 것으로 보인다.

### 3-2. 렌즈 왜곡 보정 k1
k1별로 매트 위·아래 테두리의 휨을 자동 측정했다. 휨은 가운데가 양 끝 대비 벗어난 픽셀 수이고, 1440x810 기준이다.

| k1 | 위 테두리 휨 | 아래 테두리 휨 |
|---|---|---|
| 0.00 | 19px | 28px |
| -0.30 | 14px | 23px |
| -0.50 | 10px | 16px |
| -0.54 | 7px | 16px |

- **찾은 값: k1 ≈ -0.50**. 휨이 약 절반으로 줄었다.
- 완전히 곧게 펴지지는 않는다. k1 하나짜리 모델(fx = 폭)은 k1이 약 -0.59보다 작아지면 화면 좌우 끝이 접혀서 더 펼 수 없다.
- 보정 전후 화면 캡처:
  - 보정 전: `docs/images/step22_before_k1_0.00.jpg`
  - 보정 후: `docs/images/step22_after_k1_-0.50.jpg`

### 3-3. 공 검출 면적
매트 **왼쪽 끝**의 흰 연습공을 300프레임 동안 측정했다. 흰 공 HSV 범위를 썼다.

| process_scale | k1=0 면적 (지름) | k1=-0.50 면적 (지름) |
|---|---|---|
| 1.0 | 354~374px² (23.4px) | 383~404px² (24.7px) |
| 0.75 | 185~203px² (17.5px) | 195~215px² (18.0px) |
| 0.5 | 66~74px² (10.8px) | 73~80px² (11.2px) |

- 0.75에서 예전 `min_area: 200`이면 공이 절반쯤 걸러진다. 그래서 80으로 낮췄다.
- 0.5를 쓰려면 `min_area`를 30 정도로 더 낮춰야 한다.

### 3-4. 정지한 공의 좌표 흔들림

| process_scale | 최대 흔들림 | 표준편차 |
|---|---|---|
| 1.0 | 1px | 0.1~0.5px |
| 0.75 | 1px | 0.5px 이하 |
| 0.5 | 1px | 0.1px 이하 |

- `tracking.arm_move_distance` 8px는 그대로 둔다. 흔들림(1px 이하)보다 충분히 크다. 0.75에서 8px는 매트 위 약 18mm에 해당한다.

## 4. 안 된 것 / 확인 못 한 것

- 공을 매트 **가운데·오른쪽 끝**에 놓고 검출·면적을 확인하지 못했다. 사람이 공을 옮겨야 한다.
- 매트 위에 흰 공만 있어서, 지금 활성 프로필인 **연두 공 프로필로는 공을 측정하지 못했다**. 이 프로필은 바닥 잡음을 공으로 잡고 있었다.
- 흰 공 프로필을 쓰면 오른쪽 끝의 흰 컵(홀)도 공으로 잡힐 수 있다. 컵은 면적 약 460~890px², 원형도 0.8 이상이라 `max_area` 600으로는 일부만 걸러진다.
- k1 하나짜리 모델로는 왜곡이 절반 정도만 펴진다. 더 펴려면 초점거리 가정을 바꾸거나 k2를 추가해야 한다.
- `config/settings.json`은 지시대로 `undistort_k1: 0.0`으로 커밋했다. 이 PC에서 -0.50을 쓰려면 설정창에서 저장해야 한다.
- 저장돼 있던 예전 캘리브레이션은 자동으로 무효 상태다. 캘리브레이션을 다시 해야 한다.
- 슬라이더·격자선 UI는 오프스크린 테스트로만 확인했다. 실제 창에서 조작해 보는 확인이 필요하다.
- `docs/PROTOCOL.md`의 "일반 흐름" 초안 수정은 작업 전부터 커밋 안 된 상태였다. 이번 커밋에서는 빼고 로컬에 그대로 남겼다.

## 6. 실행 방법

1. 프로그램 실행: `run_ui.bat` (다른 python·볼트래커 프로세스는 모두 종료)
2. 설정 메뉴에서 "프로필/매트 설정..."을 열고 "렌즈 왜곡 보정" 구역으로 간다.
3. "카메라 화면에 격자선 표시"를 켜고, 매트 테두리가 곧아지도록 슬라이더를 움직인다 (약 -0.50).
4. **저장**을 누른다.
5. 상단 경고 띠가 보이면 "캘리브레이션" 버튼을 눌러 다시 지정한다.
6. 공 면적 확인: "검출 디버그 표시"를 켜고 공을 여러 위치에 놓아 본다.
7. 자동 테스트:
   ```
   python -m unittest discover -s tests -v
   ```
8. 속도 확인: `logs/engine.log`의 "상태 요약" 줄에서 FPS·처리 시간·처리 화면 크기를 본다.
