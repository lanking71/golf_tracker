### 0-3. 컵에 바짝 붙어 멈춘 공 → 정지 (`VisionEngine._check_ball_at_rim`)

**문제**
- 공과 컵 사이가 약 5px보다 좁으면 블러·모폴로지 때문에 둘이 한 덩어리로 붙는다.
- 그 덩어리는 공 크기가 아니라서 공이 "사라진" 것처럼 보이고, 0.5초 뒤 홀인으로 잘못 판정됐다.

**판단** (홀인 확인 시간 0.5초 동안 컵 자리 덩어리를 매 프레임 본다)
1. 덩어리 면적 ≥ 기억한 컵 면적 + 공 예상 면적 x `hole.stuck_ball_area_fraction`(0.5)
   - 지침의 예시는 "컵 면적 x1.3"이었다.
   - 대신 "공 반 개만큼 커졌는지"를 본다. 컵 크기(현장 컵 350~575px²)와 상관없이 같은 기준이 되기 때문이다.
2. 덩어리의 가장 먼 점이 컵 중심에서 (컵 반경 + 공 반경 x 0.5) 넘게 떨어져 있음
   - 공이 컵 **안**으로 떨어져 컵 안이 하얗게 보이는 경우는 컵 밖으로 튀어나오지 않는다. 그래서 그 경우는 홀인으로 남는다.
3. **판정 시점**: 홀인 확인 시간이 끝나는 순간, 바로 앞 프레임들이 **연속 3번 이상** 1·2를 만족해야 한다.
   - 공이 컵에 떨어지는 순간에도 몇 프레임은 튀어나온 덩어리로 보일 수 있다.
   - 이 경우 공이 사라지면 연속 횟수가 0으로 돌아가므로 홀인으로 끝난다.

**끝 위치 (방법 결정)**
- 덩어리에서 컵 중심으로부터 가장 먼 점은 공의 바깥쪽 끝이다.
- 그 방향으로 (그 거리 - 공 반경)만큼 간 곳을 공 중심으로 본다. 즉 "덩어리에서 컵 쪽을 뺀 바깥쪽 끝"이다.
- 계산이 안 되면 마지막으로 본 공 위치를 쓴다.

**결과**: 종료 사유는 "정지 감지"(RESULT `reason:"STOP"`, `hole:null`)이고, 로그에 "컵 테두리에 붙어 멈춘 공 ..."이 남는다.

**테스트 (가짜 영상)**
- 공을 컵에 붙임(중심 거리 42px) → 정지. 위치 오차 6px 이내.
- 붙었다가 사라짐 → 홀인.

### 0-4. 대기 상태 전체 검색을 매트 영역만 (`VisionEngine._mat_roi`)

**바꾼 것**
- 캘리브레이션이 있으면 "화면 전체" 검색도 **매트 4점을 감싸는 사각형 + 20px 여유**만 찾는다. 검색 영역 표시 글자는 `ROI: mat`이다.
- 매트 밖 공은 어차피 매트 밖 필터에서 버려지므로 결과는 같다.

## 1. 왜 바꿨나

지금은 퍼팅 한 번에 버튼을 세 번 눌러야 했다: "캘리브레이션" → "시작 위치 등록" → "추적 준비". 사용자가 원하는 흐름은 다음과 같다.
- 캘리브레이션이 저장되어 있고 유효하면 버튼 없이 바로 쓴다 (25단계 설정 분리로 값이 유지된다).
- 시작 위치는 한 번 등록하면 저장한다. 그다음부터는 그 구역에 공을 놓으면 자동으로 시작점을 잡는다.
- "추적 준비" 버튼 없이, 공이 움직이면 퍼팅으로 보고 궤적을 그린다.
- 결과가 나온 뒤 공을 다시 시작 구역에 놓으면 자동으로 다음 퍼팅을 준비한다.

### 2-2. 자동 흐름 (`src/auto_flow.py` 신규, `src/engine.py`, `src/tracker.py`)

**구조**
- `AutoFlow`는 "무엇을 할지"만 판단한다. 화면·카메라·Qt를 모른다.
  - 판단 결과 종류: READY / ARM / DROP
- 엔진(`_auto_step`)이 그 결과대로 상태를 바꾸고 로그·앱 알림을 보낸다.
- 거리는 모두 매트 mm 좌표로 판단한다. 그래서 캘리브레이션이 유효할 때만 동작한다.

| 지금 상태 | 조건 | 자동 동작 |
|---|---|---|
| IDLE | 저장된 캘리브레이션이 유효 | 바로 READY (`Tracker.enter_ready`) |
| READY | 시작 구역(저장 구역 / 어드레스 / 지금 시작점) 안에 공이 1초 가만히 있음 | 시작점 등록 → ARMED |
| ARMED | 공이 `arm_move_distance_mm` 이상 움직임 | TRACKING (예전과 같음) |
| TRACKING → 정지 | 시작점에서 가장 멀리 간 거리 < 100mm + 움직이기 시작해서 1.5초 안에 멈추기 시작 | **자리 고쳐 놓기**: 결과(RESULT)를 보내지 않음. 멈춘 자리가 구역 안이면 그 자리로 다시 ARMED, 아니면 READY |
| TRACKING → 끝 | 정지 / 홀인 / 이탈 | FINISHED + DB 자동 저장 |
| FINISHED | 공을 집었다가(또는 움직였다가) 시작 구역에 다시 1초 놓음 | 다음 퍼팅 준비 → ARMED. 이전 궤적·결과는 화면에 남김 |
| ARMED | 공이 3초 넘게 안 보임 | 시작점을 지우고 READY |

**세부 규칙**
- **가만히 있음**:
  - 같은 자리(5mm 안)에서 **연속으로** 검출될 때만 센다.
  - 한 프레임이라도 못 찾거나 벗어나면 처음부터 다시 센다.
  - 공을 놓는 손·발이 잠깐 만든 덩어리를 공으로 오해하지 않기 위해서다.
- **짧은 퍼팅으로 구역 안에서 멈춘 공** (지침의 "방법을 정해 주석으로 설명"):
  - "다시 놓기 대기(hold)"를 둔다.
  - 끝난 뒤에는 공이 0.3초 이상 사라지거나(집어 감) 멈춘 자리에서 20mm 넘게 움직여야 다음 준비를 받는다.
  - 공이 구역 밖에서 멈췄으면 그 공은 구역 검색에 안 보이므로 바로 다음 공을 받는다.
  - 최소 대기 시간 방식은 쓰지 않았다. 그대로 두면 계속 기다리는 쪽이 사람 의도에 맞아서다.
- **이전 궤적 남기기**:
  - 다음 준비 때는 `register_start_position`·`start_tracking`에 `keep_previous=True`를 준다.
  - 그러면 궤적·결과를 지우지 않는다.
  - 다음 퍼팅이 실제로 시작될 때(TRACK START) 궤적이 새로 시작된다.
- **퍼터가 공을 가림**: ARMED에서는 3초 전까지 상태를 유지한다.
- **구역 안 후보가 여러 개**: READY·FINISHED에서는 시작 구역 원만 검색한다. 검출기가 그 중심에 가장 가까운 후보를 고른다(`prefer`).
- **버튼 우선**:
  - 화면 버튼과 앱 명령은 예전 그대로 동작하고, 자동 흐름은 그 결과 상태에서 이어 간다.
  - '추적 중지'·'궤적 초기화'(ABORT/RESET) 뒤에는 다시 놓기 대기를 건다.
  - 그래서 공이 그대로 있으면 자동으로 다시 준비하지 않는다.
- **Tracker 추가 기능**:
  - `enter_ready`
  - `keep_previous`
  - `stop_started_at` (공이 멈추기 시작한 시각)
  - `lost_hole` / `lost_since` / `hole_confirm_due`
  - `finish_at_rim`

### 2-3. 시작 구역 등록·저장
- 처음 한 번 "시작 위치 등록"(앱의 `INIT`)을 하면 그 자리가 `auto.start_zone`으로 현장 파일에 저장된다. 구역이 이미 있으면 바꾸지 않는다.
- 앱이 `SET_ADDR`로 어드레스를 정하면 그 위치를 시작 구역으로 쓴다.
  - 저장은 하지 않는다. 기존 ADDR처럼 엔진을 다시 켜면 없어진다.
- 메뉴 **설정 > 시작 구역 지우기**: 지우면 다음 "시작 위치 등록" 때 새로 저장된다.
- 시작 구역이 없고 `anywhere`도 false면 안내만 한다: "시작 위치 등록을 한 번 해 주세요".
- 시작 구역은 매트 mm 좌표다. 캘리브레이션을 다시 해도 그대로 쓴다.

### 2-4. 검색 영역
- READY(시작점 없음)와 FINISHED에서는 시작 구역 원(반경 + 50mm)만 찾는다. 검색 영역 표시 글자는 `ROI: zone`이다.
- `anywhere` 모드에서는 매트 영역에서 찾는다. 홀컵 주변은 시작점으로 받지 않는다.
- 나머지 상태는 24단계 규칙을 그대로 쓴다. 다만 "전체"는 매트 영역이다 (0-4).

### 2-6. 프로토콜 2.5 (호환되는 추가, `docs/PROTOCOL.md`)
- `HELLO`: `"auto": true/false`, `"start_zone": {"x_mm","y_mm","radius_mm"} | null`
- 새 명령 `{"cmd":"AUTO","enabled":true|false}`
  - 응답: `{"cmd":"AUTO","result":"OK","enabled":..,"start_zone":..}`
  - 현장 파일에 저장된다.
  - `enabled`가 없으면 지금 값만 알려 준다. 잘못된 값이면 NG `bad_value`.
- 이벤트 `{"cmd":"INIT","event":"AUTO","x":..,"y":..}`: 자동 시작점. 이어서 `STATUS(ARMED)`가 간다.
- 이벤트 `{"cmd":"TRACK","event":"CANCEL","reason":"READDRESS"}`: `RESULT`는 보내지 않는다.
  - 상태는 TRACKING에서 바로 ARMED(또는 READY)로 간다. `STATUS(FINISHED)`는 나가지 않는다.
- 컨트롤의 `INIT`/`ADD`/`ABORT`/`RESET`은 예전과 같다. 직접 조종하려면 `AUTO false`를 보내면 된다 (문서에 명시).
