## 1. 왜 바꿨나
- 궤적이 카메라 창 **아래의 별도 창**(매트 비율 빈 캔버스)에 그려져서 실제 화면과 같이 보기 어려웠다.
- 캘리브레이션한 측정 영역 전체(예: 3000x1000mm)를 위에서 반듯하게 펼친 화면으로 보고 싶다는 요구가 있었다.

---

## 2. 바뀐 화면 배치

```
 [상태] [자동] [좌표] [시작점] [정지점] [앱] [FPS]
 [ 안내 띠 (자리는 항상 확보) ]
 [카메라 보기][전체 보기]                 | 캘리브레이션
 +--------------------------------------+ | 시작 위치 등록
 |                                      | | 추적 준비 / 추적 중지
 |  카메라 창 (예전 아래 궤적 창 자리까지  | | 궤적 초기화 / 저장
 |  모두 차지, 비율 유지하며 커짐)         | | 고정 물체 다시 찾기
 |                                      | | [요약 통계]
 +--------------------------------------+ |
```

- **아래 궤적 창(`trajectory_label`)을 없앴다.** 그 자리만큼 카메라 창이 커졌다.
- **요약 통계 패널은 오른쪽 버튼 열 바로 아래**로 옮겼다. 갱신 방식(`_update_stats_panel`)은 그대로다.
- 카메라 창 바로 위에 보기 전환 버튼 2개를 두었다: **"카메라 보기" / "전체 보기"**
  - `QButtonGroup`(하나만 선택)으로 묶었다.
  - 선택된 버튼은 골드, 나머지는 기본 초록 버튼이다 (`QPushButton#view_toggle:checked`, `src/ui/styles.py`).
- 창 크기를 바꾸면 다음 프레임에 비율을 유지하며 다시 그려진다 (기존 `_frame_to_pixmap` 동작).

## 3. 구현 내용

### 3-1. 카메라 보기에 궤적 직접 그리기 (`src/ui/main_window.py`)
- `_compose_camera_view()`가 처리 프레임 위에 다음 순서로 그린다. 궤적이 공 표시를 가리지 않게 하기 위해서다.

  격자선 → 매트 윤곽선·시작 구역 → **궤적** → 디버그(검색 영역·후보·고정 물체) → 공 검출 → 시작점 → 캘리브레이션 모서리

- 궤적은 `_paint_trajectory()`를 처리 프레임 픽셀 좌표 그대로 불러서 그린다.
  - 그리는 것: 경로 선(큰 점프 구간은 끊음), 현재 위치(흰 점), 정지점(골드 링)
  - 시작점은 기존 시작점 표시(골드 십자 + 링)를 쓴다.
  - 캘리브레이션 중(모서리 찍기)에는 궤적을 그리지 않는다.
- 선 두께는 2 → **3px**로 바꿨다. 1440x810 화면을 창 크기로 줄여 보여도 잘 보이게 하기 위해서다.
- 궤적이 지워지는 시점은 예전과 같다: 다음 퍼팅이 시작될 때(TRACK START).
  - 그 전까지는 이전 궤적이 남는다 (26단계 자동 흐름 그대로).
- 설정 > 프로필/매트 설정에 **"카메라 화면에 궤적 표시"** 체크박스를 넣었다.
  - 기본은 켬이다.
  - 바로 적용되고 현장 파일 `ui.show_trajectory`에 저장된다.

### 3-2. 전체 보기 (`src/ui/mat_view.py` 신규 + `main_window._compose_mat_view`)
- **변환**:
  - 출력 픽셀 = `S @ calibration.matrix` @ 처리 프레임 픽셀
  - S = mm → 출력 픽셀 비율
  - 이 행렬로 `cv2.warpPerspective` 한다.
  - S와 합친 행렬은 캘리브레이션 행렬·매트 크기·출력 크기가 바뀔 때만 다시 계산한다 (`MatView._update`).
- **출력 크기**: 가로 1440px, 세로는 매트 비율이다.
  - 3000x1000mm면 1440x480, 4500x2000이면 1440x640.
  - 매트 좌상단 모서리가 출력 (0, 0)이다.
- 그 위에 mm 좌표로 그리는 것:

| 대상 | 표시 |
|---|---|
| 시작 구역 | 자동 모드일 때 얇은 골드 원 |
| 홀컵 | 파란 원 + H번호. 반경은 고정 물체 반경을 mm로 바꿔 계산 |
| 궤적 | 시작점·경로·현재 위치·정지점. 예전 아래 창의 mm 캔버스 방식을 재사용 |
| 지금 공 위치 | 흰 원(반지름 21.3mm) + 빨간 중심점 |

- 디버그 표시(검색 영역·후보)는 카메라 좌표 기준이라 전체 보기에서는 그리지 않는다.
- **보기 선택 규칙** (`_effective_view`):
  - 캘리브레이션이 없거나 무효면 "전체 보기" 버튼이 비활성이 되고 카메라 보기로 보여준다.
  - 다음 경우에는 사용자가 전체 보기를 골랐어도 **잠시 카메라 보기**로 바뀐다. 카메라 화면을 클릭해야 하기 때문이다.
    - 캘리브레이션 중(모서리 찍기)
    - 색 잡기 중
    - HSV 튜닝 미리보기 중
  - 끝나면 원래 보기로 돌아온다.
  - 캘리브레이션이 무효가 돼도 같은 방식으로 카메라 보기가 된다.
- 마지막에 고른 보기는 현장 파일 `ui.view_mode`(`"camera"` / `"mat"`)에 저장되고, 다시 켜면 그대로다.
- **높이가 있는 물체**(다리, 퍼터, 컵 테두리)는 비스듬히 늘어나 보인다. 바닥면 기준 변환이라 정상이다 (`config/settings.md`와 `src/ui/mat_view.py` 주석에 적음).
- **처리 시간**:
  - 펼치기는 화면 그리기 쪽에서만 한다. 엔진 처리와는 따로다.
  - 화면 그리기 시간을 10초마다 로그에 남긴다: "화면 그리기 - 보기 ..., 평균 ...ms".

### 3-4. 테스트 (`tests/test_view_modes.py` 신규 10개, offscreen)

| 테스트 | 내용 |
|---|---|
| 카메라 보기 궤적 | 공이 지나간 자리의 픽셀이 궤적 색(라임), 궤적 없는 자리는 매트 색 |
| 궤적 표시 끔 | 같은 자리가 매트 색, `ui.show_trajectory` 저장 |
| 아래 창 없음 | `trajectory_label` 없음, 통계 패널은 보임 |
| 전체 보기 크기·모서리 | 4500x2000 → 1440x640, 매트 네 모서리가 출력 네 모서리로 감 (1px 이내) |
| 공 위치 | 알려진 위치의 공 → 같은 mm 위치에 빨간 중심점 |
| 전체 보기 궤적 | 지나간 자리의 mm 위치에 궤적 색 |
| 캘리브레이션 없음 | "전체 보기" 비활성, 골라도 카메라 보기 |
| 무효가 되면 | 카메라 보기로 복귀 + "카메라 보기" 버튼 선택 |
| 캘리브레이션·색 잡기 | 카메라 보기로 바뀌었다가 끝나면 전체 보기로 복귀 |
| 저장·복원 | `ui.view_mode` 저장, 새 창이 같은 보기로 시작 |

- 위젯 테스트를 위해 공통 준비 코드(`tests/base.py`)를 바꿨다. 이제 화면 없는(offscreen) `QApplication`을 만든다 (예전 `QCoreApplication`).

## 4. 측정 결과 (실제 카메라, 사람 조작 없이, 이 PC 설정의 임시 복사본, 창 1600x900)

| 보기 | 화면 그리기 평균 | 상위 5% | 엔진 FPS | 엔진 처리 평균 |
|---|---|---|---|---|
| 카메라 보기 | 6.9ms | 10.3ms | 53.6 | 11.3ms |
| 전체 보기 | **6.2ms** | 8.2ms | 51.9 | 10.5ms |

- 전체 보기가 느리지 않다. 펼치기(warpPerspective)가 더해지지만, 출력이 1440x480으로 카메라 프레임(1440x810)보다 작다. 그래서 화면으로 줄이는 시간이 줄어 서로 비슷하다.
- 엔진 FPS 차이(53.6 / 51.9)는 측정 때마다 생기는 흔들림 정도다.
- **화면 확인 결과** (캡처):
  - 카메라 보기에서 매트 윤곽·시작 구역 원이 나왔다.
  - 전체 보기에서 측정 영역이 3:1 직사각형으로 꽉 차고, 오른쪽 끝 컵 3개 위에 파란 원·홀 번호가 맞게 겹쳤다.
- 전체 보기에서 보니 **이 PC의 고정 물체 목록에 아직 신발 2개(왼쪽 위 큰 파란 원)가 남아 있다.** 그래서 컵 번호도 H3~H5로 나온다.
  - 26단계 7-2에서 안내한 "고정 물체 다시 찾기"를 한 번 해야 한다.

## 5. 안 된 것 / 확인 못 한 것
1. 실제 퍼팅 중 궤적이 공을 따라 그려지는지, 다음 퍼팅 때 지워지는지: 현장 확인 대기 (가짜 영상 테스트로만 확인).
2. 창 크기를 바꾸며 보는 확인과 사용자 캡처 2장: 현장 확인 대기.
3. 전체 보기에서 디버그 표시(검색 영역·후보)는 그리지 않는다.
4. 이 PC: "고정 물체 다시 찾기"를 아직 하지 않아서 신발 2개가 홀 1·2번으로 남아 있다.
5. exe 재빌드는 하지 않았다.

## 6. 현장에서 할 일
1. 프로그램을 다시 켠다 (`run_ui.bat`). 매트 위에 사람이 없을 때 **"고정 물체 다시 찾기"** → 컵이 H1~H3이 되는지 본다.
2. **카메라 보기**: 퍼팅하면 공을 따라 라임색 궤적이 그려지고, 다음 퍼팅이 시작될 때 지워지는지 본다.
3. **전체 보기**:
   - 측정 영역이 반듯한 3:1 직사각형으로 꽉 차게 보이는지
   - 컵(H1~H3)과 시작 구역 원이 실제 위치와 맞는지
   - 궤적이 공을 따라 그려지는지
4. 두 보기를 오가며 상단 FPS 배지가 크게 떨어지지 않는지 본다. `logs/engine.log`의 "화면 그리기" 줄로도 볼 수 있다.
5. 창 크기를 바꿔 보고, 캡처 2장(카메라 보기, 전체 보기)을 보내 주세요.
