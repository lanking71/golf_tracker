# Flutter 게임 ↔ 비전 엔진 연동 가이드

- 대상: 비전 엔진에서 **골프공 궤적 좌표를 받아 게임을 진행하는 Flutter 게임** 개발자
- 엔진 프로토콜 버전: **2.5**
- 이 문서는 "게임에서 어떻게 쓰면 되는가"를 설명합니다. 명령·필드 하나하나의 상세 규격은 [PROTOCOL.md](PROTOCOL.md)에 있습니다.

---

## 1. 비전 엔진이 하는 일 (한 문단 요약)

천장에 달린 카메라 1대가 퍼팅 매트를 내려다봅니다. 엔진(Windows PC 프로그램)은 공을 찾아서 **매트 위 실제 위치(mm)**로 바꿉니다. 그리고 퍼팅이 시작되면 실시간 좌표를, 끝나면 결과(거리·속도·궤적 전체·홀인 여부)를 **TCP로 게임에 보냅니다.** 공 놓기 → 퍼팅 감지 → 결과 판정은 엔진이 스스로 진행합니다(자동 흐름). 그래서 게임은 **이벤트를 받아서 화면에 그리기만 하면 됩니다.**

```
 [카메라] ──▶ [비전 엔진 PC] ──TCP 9000, 한 줄 JSON──▶ [Flutter 게임]
                  · 공 검출                              · 공 애니메이션
                  · mm 좌표 변환                          · 게임 규칙·점수
                  · 퍼팅 시작/끝/홀인 판정                 · 연출
```

현재 설치된 매트(개발용 현장):

| 항목 | 값 |
|---|---|
| 측정 영역 | 가로 3000mm × 세로 1000mm (다른 현장은 4500 × 2000 등) |
| 홀컵 | 매트 오른쪽 끝에 3개. 위에서부터 1·2·3번 |
| 공 | 흰 연습공 (지름 42.67mm) |
| 엔진 처리 속도 | 약 50~56 FPS |
| 실시간 좌표 전송 | 추적 중 초당 최대 30회 |

## 2. 좌표계

```
 (0,0) ────────────── x (mm) ──────────────▶ (3000, 0)
   │   ● 시작 구역                         ◯ 1번 컵
   │   (공을 놓는 곳)                       ◯ 2번 컵
   y                                        ◯ 3번 컵
   ▼
 (0,1000)                                   (3000,1000)
```

- 단위는 **mm**입니다. 원점은 측정 영역의 **좌상단**이고, x는 오른쪽, **y는 아래쪽**입니다 (화면 좌표와 같은 방향).
- 퍼팅 방향은 보통 **+x 방향**입니다 (왼쪽 시작 구역 → 오른쪽 컵).
- 홀컵 위치는 접속하자마자 오는 `HELLO.holes`에 mm로 들어 있습니다.
- 시작 구역은 `HELLO.start_zone`에 들어 있습니다: `{"x_mm","y_mm","radius_mm"}` 또는 `null`.

### 게임 화면 좌표로 바꾸기
매트를 게임 화면(또는 게임 월드)의 사각형에 그대로 대응시키면 됩니다.

```dart
/// 매트 mm 좌표 → 게임 화면 좌표
class MatMapper {
  MatMapper({required this.matWidthMm, required this.matHeightMm, required this.view});

  final double matWidthMm;   // 예: 3000
  final double matHeightMm;  // 예: 1000
  final Rect view;           // 게임 화면에서 매트를 그릴 사각형 (비율을 맞춰 두세요)

  Offset toView(double xMm, double yMm) => Offset(
        view.left + xMm / matWidthMm * view.width,
        view.top + yMm / matHeightMm * view.height,
      );

  double mmToViewLength(double mm) => mm / matWidthMm * view.width;
}
```

> **현재 제약**: 매트 크기(mm)는 아직 `HELLO`에 들어 있지 않습니다 (엔진에 추가 요청 중, 8절). 당분간은 **게임 설정값으로 현장 매트 크기(3000×1000)를 넣어 주세요.**

## 3. 게임에서 권장하는 방식: 자동 흐름 (기본)

엔진의 자동 흐름이 켜져 있으면(기본값, `HELLO.auto == true`) 게임은 **명령을 하나도 보내지 않아도 됩니다.** 접속해서 이벤트만 들으면 됩니다.

### 3-1. 한 번의 퍼팅에서 받는 메시지 순서

```
 플레이어 동작               엔진 → 게임 메시지                       게임이 할 일
 ─────────────────────────────────────────────────────────────────────────────────
 (게임 접속)               HELLO, STATUS(READY)                     매트·컵 그리기, "공을 놓으세요"
 공을 시작 구역에 놓음 ──▶  INIT event:AUTO (x,y)  → STATUS(ARMED)  공을 그 자리에 표시, "퍼팅하세요"
 퍼팅!                ──▶  TRACK event:START                        샷 시작 연출, 궤적 버퍼 초기화
 공이 구름                  STATUS(TRACKING) x,y,t,speed  (~30Hz)  공 애니메이션
 공이 멈춤/컵인/이탈   ──▶  STATUS(FINISHED) → RESULT               결과 판정·점수·리플레이
 공을 집어 다시 놓음   ──▶  INIT event:AUTO → STATUS(ARMED)         다음 샷 준비
```

### 3-2. 게임 쪽 상태 처리표

| 받은 메시지 | 조건 | 게임 동작 |
|---|---|---|
| `HELLO` | 접속 직후 1번 | 홀컵(`holes`), 시작 구역(`start_zone`), `calibrated` 저장. `calibrated == false`면 "엔진 설정 필요" 안내 |
| `STATUS` | `state == "READY"` | "공을 시작 구역에 놓으세요" |
| `INIT` + `event == "AUTO"` | 공이 놓임 | 공을 (x, y)에 그림 |
| `STATUS` | `state == "ARMED"` | "준비 완료 - 퍼팅하세요". 공 위치 고정 |
| `TRACK` + `event == "START"` | 퍼팅 시작 | 샷 시작. 궤적 버퍼를 비움 |
| `STATUS` | `state == "TRACKING"` | `x`, `y`로 공 이동. **`x`/`y`가 `null`이면 마지막 위치 유지** (공이 잠깐 가려짐) |
| `TRACK` + `event == "CANCEL"` | 퍼팅이 아니었음 (공 자리 고쳐 놓기) | **샷을 무효 처리**하고 연출을 되돌림. 이 샷의 `RESULT`는 오지 않음 |
| `STATUS` | `state == "FINISHED"` | 공 이동 멈춤. `RESULT`를 기다림 (바로 뒤에 옴) |
| `RESULT` | `reason == "HOLE_IN"` | `hole`번 컵 홀인 연출 |
| `RESULT` | `reason == "STOP"` | 공이 `stop` 위치에 멈춤 |
| `RESULT` | `reason == "LOST"` | 공이 매트 밖으로 나감 (OB 처리 등) |
| `CAMERA` | `event == "LOST"` / `"OK"` | 카메라 끊김 안내 / 해제 (엔진이 1초마다 자동 재연결) |
| (연결 끊김) | | 재접속 (5절). 다시 접속하면 `HELLO`가 다시 옴 |

> **주의 (CANCEL)**: `TRACK START`가 왔다고 해서 항상 진짜 퍼팅은 아닙니다. 공을 놓으면서 퍼터로 살짝 건드린 경우(100mm 미만 이동 후 1.5초 안에 멈춤)는 엔진이 `TRACK CANCEL`을 보내고 다시 준비 상태가 됩니다. **점수 처리는 반드시 `RESULT`를 받은 뒤에** 하세요.

### 3-3. 직접 조종 방식 (선택)
게임이 "지금은 샷을 받지 않음" 같은 단계를 직접 정하고 싶으면 `{"cmd":"AUTO","enabled":false}`를 보내고, 예전 방식(`INIT` → `ADD`)으로 조종합니다. 자세한 내용은 [PROTOCOL.md](PROTOCOL.md)의 "일반 흐름"을 보세요. **처음에는 자동 흐름으로 시작하는 것을 권장합니다.**

## 4. 공 움직임을 화면에 그리기

### 4-1. 실시간 (`STATUS`, 추적 중)
- 추적 중에는 초당 최대 30번 `STATUS`가 옵니다. 게임 화면은 보통 60fps라서, 받은 좌표로 **순간 이동시키면 공이 끊겨 보입니다.**
- 권장: 마지막으로 받은 두 점 사이를 **보간**합니다. 또는 받은 좌표를 목표로 두고 매 프레임 조금씩 따라가게 합니다.
- 카메라·엔진 처리·네트워크를 합치면 화면은 실제 공보다 조금 늦습니다. 예상치는 수십~100ms 정도이고, **아직 실측하지 않았습니다**. 같은 PC나 유선 LAN이면 더 짧습니다. 실시간 연출에는 대체로 문제없는 수준으로 예상합니다.
- `t`는 퍼팅 시작(TRACK START)을 0으로 센 경과 시간(초)입니다. 메시지가 늦게 도착해도 `t`로 정확한 시간축을 만들 수 있습니다.
- `speed`는 순간 속도(mm/초)입니다. 굴림 소리나 이펙트 세기에 쓸 수 있습니다.

### 4-2. 최종 결과 (`RESULT.points`)
- `RESULT`에는 궤적 전체가 들어 있습니다. 점마다 `[x, y, t, dist, speed]`입니다 (`fields` 참고).
- 실시간 `STATUS`는 중간에 빠질 수 있습니다. 반면 `points`는 엔진이 기록한 **전체 궤적**이므로 **리플레이·궤적 선·점수 계산에는 `points`를 쓰세요.**
- `points`의 시간 간격은 일정하지 않습니다 (일정 거리 이상 움직일 때마다 기록). 리플레이할 때는 `t`를 기준으로 재생하세요.
- `HOLE_IN`일 때 `stop`은 **컵 중심**이고, `points`의 마지막 점은 공이 사라지기 직전 위치입니다.

### 4-3. 실제 매트보다 긴 가상 그린을 쓰는 경우
게임 코스가 실제 매트(3m)보다 길면, 공이 매트 끝에 닿거나 매트 밖으로 나가기 전에 **출발 속도와 방향**으로 나머지 거리를 물리 계산해야 합니다. 지금은 게임에서 `points`(또는 실시간 `STATUS`)의 처음 부분으로 계산하면 됩니다.

```dart
import 'dart:math';

/// RESULT.points 의 처음 [window]초 구간으로 출발 속도(mm/s)와 방향(도)을 구한다.
/// 방향: +x(매트 긴 쪽, 컵 방향) = 0도, 아래쪽(+y)으로 휘면 + 값.
({double speed, double angleDeg})? launchFromPoints(List points, {double window = 0.15}) {
  if (points.length < 2) return null;
  final p0 = points.first as List;
  List? last;
  for (final p in points.skip(1)) {
    final q = p as List;
    if ((q[2] as num) > window) break;
    last = q;
  }
  last ??= points[1] as List;
  final dt = (last[2] as num).toDouble() - (p0[2] as num).toDouble();
  if (dt <= 0) return null;
  final dx = (last[0] as num).toDouble() - (p0[0] as num).toDouble();
  final dy = (last[1] as num).toDouble() - (p0[1] as num).toDouble();
  return (
    speed: sqrt(dx * dx + dy * dy) / dt,
    angleDeg: atan2(dy, dx) * 180 / pi,
  );
}
```

> 출발 속도·방향을 엔진이 직접 계산해서 보내 주는 기능은 엔진에 추가 요청 중입니다 (8절). 추가되면 이 계산은 필요 없습니다.

## 5. 연결 코드 (Dart)

[PROTOCOL.md의 `VisionClient`](PROTOCOL.md)에 **자동 재접속**과 **게임용 이벤트 분류**를 더한 예시입니다.

> 참고용 예시입니다. 엔진 개발 환경에 Dart가 없어서 **직접 실행해 보지는 못했습니다.** 프로토콜 자체는 엔진 쪽에서 실제 TCP 소켓으로 시험했습니다.

```dart
import 'dart:async';
import 'dart:convert';
import 'dart:io';

/// 게임이 쓰기 쉬운 형태로 바꾼 엔진 이벤트
sealed class VisionEvent {}
class EngineHello extends VisionEvent {
  EngineHello(this.raw);
  final Map<String, dynamic> raw;
  bool get calibrated => raw['calibrated'] == true;
  bool get auto => raw['auto'] == true;
  List<Map<String, dynamic>> get holes => (raw['holes'] as List? ?? []).cast<Map<String, dynamic>>();
  Map<String, dynamic>? get startZone => raw['start_zone'] as Map<String, dynamic>?;
}
class StateChanged extends VisionEvent { StateChanged(this.state); final String state; }
class BallPlaced extends VisionEvent { BallPlaced(this.x, this.y); final double x, y; }
class ShotStarted extends VisionEvent { ShotStarted(this.ts); final int ts; }
class BallMoved extends VisionEvent {               // 추적 중 실시간 좌표
  BallMoved(this.x, this.y, this.t, this.speed);
  final double? x, y;                                // 공이 잠깐 안 보이면 null
  final double t;
  final double? speed;
}
class ShotCancelled extends VisionEvent {}           // 퍼팅이 아니었음 (RESULT 없음)
class ShotResult extends VisionEvent {
  ShotResult(this.raw);
  final Map<String, dynamic> raw;
  String get reason => raw['reason'] as String;      // STOP / LOST / HOLE_IN
  int? get hole => raw['hole'] as int?;
  double? get distanceMm => (raw['distance_mm'] as num?)?.toDouble();
  List get points => raw['points'] as List? ?? const [];
}
class CameraChanged extends VisionEvent { CameraChanged(this.ok); final bool ok; }
class Connection extends VisionEvent { Connection(this.connected); final bool connected; }

class VisionService {
  VisionService(this.host, {this.port = 9000});
  final String host;
  final int port;

  final _events = StreamController<VisionEvent>.broadcast();
  Stream<VisionEvent> get events => _events.stream;

  Socket? _socket;
  bool _closing = false;
  int _nextId = 1;
  final _pending = <int, Completer<Map<String, dynamic>>>{};
  String? _lastState;

  /// 접속을 시작한다. 끊기면 2초 뒤 자동으로 다시 접속한다.
  Future<void> start() async {
    _closing = false;
    while (!_closing) {
      try {
        final s = await Socket.connect(host, port, timeout: const Duration(seconds: 3));
        s.setOption(SocketOption.tcpNoDelay, true);
        _socket = s;
        _events.add(Connection(true));
        await s
            .cast<List<int>>()
            .transform(utf8.decoder)
            .transform(const LineSplitter())
            .forEach(_onLine); // 연결이 끊길 때까지 여기서 기다린다
      } catch (_) {
        // 접속 실패 또는 끊김 → 아래에서 재시도
      }
      _socket = null;
      _lastState = null;
      for (final c in _pending.values) {
        c.completeError(const SocketException('엔진과 연결이 끊어졌습니다'));
      }
      _pending.clear();
      _events.add(Connection(false));
      if (!_closing) await Future.delayed(const Duration(seconds: 2));
    }
  }

  void _onLine(String line) {
    Map<String, dynamic> m;
    try {
      m = jsonDecode(line) as Map<String, dynamic>;
    } catch (_) {
      return;
    }
    final id = m['id'];
    if (id is int && _pending.containsKey(id)) {
      _pending.remove(id)!.complete(m); // 내가 보낸 명령의 응답
      return;
    }
    switch (m['cmd']) {
      case 'HELLO':
        _events.add(EngineHello(m));
      case 'STATUS':
        final state = m['state'] as String;
        if (state != _lastState) {
          _lastState = state;
          _events.add(StateChanged(state));
        }
        if (state == 'TRACKING') {
          _events.add(BallMoved((m['x'] as num?)?.toDouble(), (m['y'] as num?)?.toDouble(),
              (m['t'] as num? ?? 0).toDouble(), (m['speed'] as num?)?.toDouble()));
        }
      case 'INIT' when m['event'] == 'AUTO':
        _events.add(BallPlaced((m['x'] as num).toDouble(), (m['y'] as num).toDouble()));
      case 'TRACK' when m['event'] == 'START':
        _events.add(ShotStarted(m['ts'] as int));
      case 'TRACK' when m['event'] == 'CANCEL':
        _events.add(ShotCancelled());
      case 'RESULT' when m['result'] == null: // result 필드가 있으면 GET_RESULT의 응답
        _events.add(ShotResult(m));
      case 'CAMERA':
        _events.add(CameraChanged(m['event'] == 'OK'));
    }
  }

  /// 명령을 보내고 응답을 기다린다 (예: {'cmd':'PING'}, {'cmd':'GET_RESULT'}).
  Future<Map<String, dynamic>> request(Map<String, dynamic> command,
      {Duration timeout = const Duration(seconds: 5)}) {
    final s = _socket;
    if (s == null) return Future.error(const SocketException('엔진에 연결되어 있지 않습니다'));
    final id = _nextId++;
    final c = Completer<Map<String, dynamic>>();
    _pending[id] = c;
    s.write('${jsonEncode({...command, 'id': id})}\n');
    return c.future.timeout(timeout, onTimeout: () {
      _pending.remove(id);
      throw TimeoutException('${command['cmd']} 응답 없음');
    });
  }

  Future<void> stop() async {
    _closing = true;
    await _socket?.close();
  }
}
```

사용 예:
```dart
final vision = VisionService('192.168.0.10'); // 엔진 PC 주소
vision.events.listen((e) {
  switch (e) {
    case EngineHello h:   game.setupCourse(holes: h.holes, startZone: h.startZone);
    case BallPlaced b:    game.placeBall(mapper.toView(b.x, b.y));
    case ShotStarted _:   game.beginShot();
    case BallMoved m:     if (m.x != null) game.moveBallTo(mapper.toView(m.x!, m.y!), m.t);
    case ShotCancelled _: game.cancelShot();
    case ShotResult r:    game.finishShot(r);   // 점수 처리는 여기서
    case CameraChanged c: game.showCameraWarning(!c.ok);
    case Connection c:    game.showConnected(c.connected);
    case StateChanged _:  break;
  }
});
vision.start();
```

**재접속할 때**: 다시 접속하면 `HELLO`와 현재 `STATUS`가 바로 옵니다. 끊긴 동안 끝난 샷의 결과는 `{"cmd":"GET_RESULT"}`로 다시 받을 수 있습니다 (마지막 1개).

## 6. 플랫폼·네트워크 체크리스트

| 항목 | 내용 |
|---|---|
| **Flutter Web** | **사용 불가.** 브라우저는 일반 TCP 소켓을 쓸 수 없습니다. 웹으로 만들어야 하면 엔진에 WebSocket 지원을 추가해야 하니 미리 알려 주세요 |
| Windows / Android / iOS / macOS / Linux 앱 | `dart:io`의 `Socket`으로 동작 |
| 네트워크 | 게임 기기와 엔진 PC가 **같은 네트워크**. 엔진 PC의 Windows 방화벽에서 **TCP 9000 허용** |
| 같은 PC에서 실행 | 주소 `127.0.0.1` |
| Android 에뮬레이터 → 같은 PC의 엔진 | 주소 `10.0.2.2` |
| Android 권한 | `AndroidManifest.xml`에 `INTERNET` |
| iOS | 로컬 네트워크 접근 허용 (`NSLocalNetworkUsageDescription`) |
| 여러 기기 동시 접속 | 가능. 이벤트는 모두에게, 명령 응답은 보낸 기기에만 |

## 7. 자주 생기는 상황

| 상황 | 게임에서 보이는 것 | 처리 |
|---|---|---|
| 공을 놓다가 퍼터로 툭 건드림 | `TRACK START` → `TRACK CANCEL` | 샷 무효. 다시 `INIT AUTO` → `ARMED`가 옴 |
| 퍼터·발이 공을 잠깐 가림 | 준비 중이면 아무 일 없음. 추적 중이면 `STATUS`의 `x`/`y`가 잠깐 `null` | 마지막 위치 유지 |
| 준비 상태에서 공을 집어 감 | 3초 뒤 `STATUS(READY)` | "공을 놓으세요" |
| 공이 컵 테두리에 붙어 멈춤 | `RESULT` `reason:"STOP"` (홀인 아님) | 정지 처리 |
| 공이 컵을 스치고 나옴 (립아웃) | 추적이 계속되다가 나중에 `STOP`/`LOST` | 그대로 처리 |
| 공이 매트 밖으로 나감 | 2초 뒤 `RESULT` `reason:"LOST"` | OB 등 |
| 카메라 케이블 빠짐 | `CAMERA LOST`. 추적 중이면 2초 뒤 `RESULT LOST` | 경고 표시. 복구되면 `CAMERA OK` |
| 엔진 설정이 바뀌어 캘리브레이션 무효 | `HELLO.calibrated == false`, 자동 흐름 멈춤 | "엔진 캘리브레이션 필요" 안내 (엔진 PC에서 담당자가 처리) |

## 9. 시작 순서 (게임 개발자)

1. 엔진 담당자에게 받을 것: 엔진 PC의 IP 주소, 현장 매트 크기
2. 5절 `VisionService`로 접속 → `HELLO`가 오는지 확인 (홀컵 3개, `auto: true`)
3. 공을 시작 구역에 놓고 → `INIT AUTO`, `STATUS(ARMED)` 확인
4. 퍼팅 → `TRACK START`, 실시간 `STATUS`, `RESULT` 확인
5. 2절 `MatMapper`로 게임 화면에 공 그리기 → 4절 보간·리플레이
6. 7절 상황들을 하나씩 처리

엔진 PC 없이 메시지 흐름만 먼저 보고 싶으면, 엔진 저장소의 `tools/test_client.py`로 엔진에 접속해 실제 메시지를 눈으로 확인할 수 있습니다 (엔진 담당자가 실행).
